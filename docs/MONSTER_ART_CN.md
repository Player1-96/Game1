## 0. 一页结论

**三个真正的病根（都不是「画得少」，是「结构上没有」）**：

| # | 病根 | 一句话证据 |
| --- | --- | --- |
| ① | **出手没有预备动作** | 12 只怪里只有 4 只有真前摇（血蝠 / 玄光瞳 / 玄甲卫 / 蹦山魈）。其余 7 只（蟾蜍 / 鬼修 / 剑灵 / 铁魄 / 阴煞 / 邪祟 / 尸傀）是 `--this.cd <= 0` **当帧就把弹发出来**，玩家只能"看见弹"才知道它出手了 |
| ② | **动画没有"动作"，只有"抖动"** | 每只怪固定 2 帧，且由**全局一句** `if (this.t % 16 === 0) this.frame = frame ? 0 : 1` 翻转 —— 跟它正在做什么毫无关系。邪祟两帧只差 **1 像素上下**；攻击时唯一的"表演"是 `this.frame = 1`（换成另一张静止图） |
| ③ | **7 只怪剪影撞车**（✅ 已实测，不是推断） | 剪影图（`dev/preview/_preview_silhouette_cn.png`）显示：**蟾蜍妖 与 阴煞**同是宽扁椭圆（且都在第 1 层）；**尸傀 / 铁魄妖 / 玄甲卫**同是"方块 + 耸肩"；**鬼修 与 影魅**同是穹顶。详情见 1.3 |

**顺带说个反直觉的发现**：造型"简陋"（行数少）与"认不出"**不是一回事**。
行数最少的阴煞（14 行）确实认不出，但同是 14~15 行的蟾蜍、蹦山魈、邪祟都过关了
（蹦山魈靠长臂、邪祟靠耳朵）。**所以别按"行数少"来定重画名单，要按剪影实测来定** ——
这也是我把剪影图先做掉的原因。

**改法的核心是一句话**：把「2 帧静止图 + 到点发弹」换成
**「一套按动作分段的帧序列 + 一条带预备/出手/收势的状态时间轴」**，
而且**两者由同一张表驱动**（见第 3 节），这样加动作只是往表里写数据，不是往 12 个 `switch` 里塞代码。

**性价比最高的一步**：先只做 **①动作三段式**（预备 10~14 帧 / 出手 2~4 帧 / 收势 8~12 帧），
造型一律**先不动**。理由：出手可读性是**玩法**问题（玩家躲不开不是因为画得丑），
而造型是**观感**问题。先修玩法，再修观感。

### 1.2 动画机制：全局一句，与动作无关

```js
// entities.js:1652 —— 所有妖物共用，跟它正在做什么毫无关系
if (this.t % 16 === 0) this.frame = this.frame ? 0 : 1;
// 攻击时唯一的"表演"（例：spit）
this.frame = 1;          // ← 换成另一张静止图，就没了
```

- 帧数：**每只 2 帧**（`[drawXieSui(0), drawXieSui(1)]`）
- 节奏：固定 16 帧一翻（≈0.27 秒），**不随状态变化**
- 两帧差多少：
  - `drawXieSui` → `yb = frame ? 0 : 1` = **整体上下 1 像素**（几乎等于没动）
  - `drawChanChu` → `yb = frame ? 0 : 0`，只有一处 `if (frame) 鼓腮`（两帧差异 = 多一个 4×2 矩形）
  - `drawXueFu` → 翅膀 4 条线各差 3 像素（**这只算真的有扇动**）

## 2. 目标与硬约束

**目标**（按优先级，先做完上面的再动下面的）：
1. **出手可读**：任何有主动技的怪，出手前都有 ≥8 帧的**视觉预备**（帧 + 形变 + 颜色三种渠道里至少给两种）
2. **一怪一签名**：每只怪有一个**只属于它**的动作词（例如"蟾蜍的鼓腮、玄甲卫的收盾"），不看颜色也能认出
3. **待机也活着**：待机不再两帧平移，而是有呼吸/摆动/悬浮的循环节奏，且**节奏与该怪性格一致**（鬼修慢、影魅飘、铁魄顿）
4. **精英与尊者一眼可辨**：不是"放大 1.5 倍"，是**有独有的动作与出场演出**

**硬约束（破一条方案就作废）**：

1. ⚠️ **不许出现固定 RGB** —— 全部走 `PAL.*` 索引色（换色板即换画风的 27 路径是核心资产，见 ROADMAP 四之二 ④）
2. ⚠️ **不许改数值** —— 本方案只动「帧的内容」与「帧的切换时机」。若某一帧必须改判定，先单独提
3. ⚠️ **帧预算要算清** —— 现在 12 只 × 2 帧 = 24 张画布；本方案最多到 12 只 × 6 帧 = 72 张。
   单张 ≤20×20 像素，对 `buildSprites`（实测换风格烘焙 ≈122ms / 434 个素材）**影响可忽略**，
   但**要顺手核对一次**（别只看"应该没事"）
4. ⚠️ **`Enemy.draw` 的兜底不许删** —— 图集缺素材时的退让链是 2026-10-09 黑屏事故换来的

## 3. 通用框架：一张表驱动「动作时间轴 + 帧序列」

### 3.1 现在的结构（分散在 12 个 case 里）

```
switch (this.def.ai) {
  case 'spit':  ...   // ← 时序散落在这里（cd / stateT / frame 到处赋值）
  case 'caster': ...
  case 'laser': ...
}
```

问题：加一个"预备动作"要改 12 处，且**每处都要自己想清楚帧该怎么切** → 这就是为什么一直是 2 帧。

### 3.2 建议的结构：`MOB_ANIM` 表 + 通用推进器

**一张表**描述每只怪的动作分段（示意，非最终值）：

```js
/* 每只怪：待机循环 + 每个动作的 [预备 / 出手 / 收势] 三段。
   frame 是「用第几帧素材」，scaleX/scaleY 是形变，tint 是叠色（也走 PAL）。 */
const MOB_ANIM = {
  chanchu: {
    idle:  { frames: [0, 1], step: 24 },                       // 慢呼吸（蛤蟆鼓气）
    spit:  { wind: { t: 12, frames: [2, 3], sy: [0.88, 1.10] }, // 鼓腮下压 → 胀大
             fire: { t: 3,  frames: [4] },                       // 张嘴喷出
             back: { t: 10, frames: [3, 2, 0] } },               // 收腮回位
  },
  ...
};
```

配套一个**通用推进器**（约 40 行，只写一次）：

```js
// 给 Enemy 加一个动作状态机：一旦 startAct('spit')，就按表推进三段；
// 每段自己 setFrame / setSquash；到 fire 段的第一帧才真正 spawnEnemyBullet。
startAct(name) / actTick()   // ← 具体的"什么时候发弹"由表里的 fire 段决定
```

**关键收益**：
- 「发弹时机」从 AI 分支里**挪到了表里**，且**天然带前摇**（fire 段之前是 wind 段）
- 加帧 = 改表；加怪 = 加一行；**AI 分支不再需要碰动画**
- ⚠️ **发弹时机必须与现在完全一致或只延后不提前** —— 表里的 `wind.t` 就是从前摇总时长里扣出来的，
  否则就是偷偷改难度。**每一次调整都要跑 `_t_foe` / `_t_balance` 对照**

### 3.3 三段式的帧预算（建议值，可按怪性格调）

| 段落 | 帧数 | 干什么 | 表现渠道（至少两个） |
| --- | --- | --- | --- |
| **预备 wind** | 10~14（重击型 20~34） | 蓄势：缩、鼓、抬、亮 | 形变（squash）+ 换帧 + **叠色**（`PAL` 亮色描边/口腔发光） |
| **出手 fire** | 2~4 | 极短，动作爆发 | 换帧（独立的一张"发力"帧）+ 反方向形变（stretch） |
| **收势 back** | 8~12 | 回到待机 | 帧序列回退 + 形变回弹（可带一次小过冲） |

配合 `ROADMAP` 四之二 ① 的 **hitstop**（3 帧）与受击形变：**出手帧不顿，命中帧才顿** ——
顿在出手上会显得卡，顿在命中上才有打击感。

## 4. 逐怪方案（中式 12 杂兵）

## 8. 验收标准

1. **剪影测试**：12 只转纯黑，**能两两区分**（这是造型验收的第一关，也是唯一客观的一关）
2. **出图对比**：同一房间、同一帧数、同样摆位下的**改前 / 改后各一张**（ROADMAP 四之二 的既有要求）
3. **动作分解图**：每只怪把它的 `wind / fire / back` 三帧**并排画在一张图上**（这是本方案特有的验收物，
   因为"动作"是本方案的主目标）
4. **时序不倒退**：`_t_foe` / `_t_balance` / `_t_dynamic` 全绿 ——
   **任何一只怪的"首次可闪避时刻"都不得比现在更晚**（前摇可以给，但不能把 `cd` 一起缩短当成补偿）
5. **色板不破**：三套色板（中式 × 北欧 × 克苏鲁预览）下各出一次图，**不许出现固定 RGB 的色块**
6. **性能**：`buildSprites` 换风格烘焙耗时实测（基线 ≈122ms），不得翻倍

## 9. 待决问题（要用户拍板）

1. **前摇要不要连带改数值？** 补 12 帧前摇会让少数几只怪**变简单**。
   三个选项：① 就这样（玩家爽） ② 从 `cd` 里扣掉，保持难度 ③ 只给视觉不给延迟（前摇期间已经能躲）
   —— 我在第 4 节按 ① 写的，**这条最需要你定**。
2. **邪祟/尸傀要不要新增主动技？** 它们现在只有接触伤害。加"前扑"是**加判定**，
   严格说不属于"美术重制"。我倾向给邪祟加（它是一层第一个敌人，太无聊）、尸傀不加（压迫型定位）。
3. **造型重制的风格方向**：我按「**夸大体征、剪影优先、去掉对称**」写。
   如果你更想要「**更写实/更精致的细节**」，方案第 4 节的造型描述要整体重写
   （这两种方向在 16px 上几乎是对立的：细节多了剪影就糊）。
4. **要不要先做一只"样板怪"？** 建议用**蟾蜍妖**（动作最有代表性、造型改动小），
   做完给你看，风格定了再批量推进。
